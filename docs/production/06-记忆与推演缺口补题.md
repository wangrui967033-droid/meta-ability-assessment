### 2.1 答案唯一性与微判断独立检查

- 每个微判断的响应全集均为 `{NAPO, LUTI}`，选项在第二轮重新生成，不继承第一轮的占用状态。
- A1 的唯一正确响应是 NAPO；A2 的唯一正确响应是 LUTI。
- 两轮响应笛卡尔积共有 4 种：`(NAPO,NAPO)`、`(NAPO,LUTI)`、`(LUTI,NAPO)`、`(LUTI,LUTI)`；仅按项目 ID 分别评分，不使用“两个标签必须各用一次”的整组规则。
- 全分响应在 A1→A2 顺序下为 `(NAPO,LUTI)`；若顺序交换，键随项目 ID 交换。一个微判断的作答不会禁用、移动或自动填写另一个微判断的选项。
- 该设计消除的是“靠 UI 剩余项作答”的机械排除提示；是否仍存在由 Deck 一一配对结构带来的认知推断，必须在认知访谈中检查，不能声称已消除所有局部依赖。

### 7.1 规则形式化、枚举逻辑与结果

将三条规则形式化为：

```text
甲 < 乙
甲 < 丙    // 完成甲后，丙才可执行
丙 < 丁    // 丙完成前，丁被阻断
```

程序验收逻辑：

```ts
const actions = ['甲', '乙', '丙', '丁'];
const valid = permutations(actions).filter(seq =>
  seq.indexOf('甲') < seq.indexOf('乙') &&
  seq.indexOf('甲') < seq.indexOf('丙') &&
  seq.indexOf('丙') < seq.indexOf('丁')
);

const accepted = new Set(valid.map(seq => seq.join('>')));
// 提交时还要检查长度为 4，且 new Set(seq).size === 4。
```

枚举结果：24 个排列中恰有 3 个有效：

1. `甲>乙>丙>丁`；
2. `甲>丙>乙>丁`；
3. `甲>丙>丁>乙`。

三个有效排列的第一项全集为 `{甲}`，因此微判断 1 的答案唯一；排序微判断有且仅有上述 3 个可接受答案。前端不得把任意一条写死为唯一答案，后端应使用谓词或上述集合验收。

- 任何题干、素材、选项、图形部件、枚举谓词或答案变更都必须提升对应版本，不能覆盖旧数据。
- 所有随机形态和选项顺序都必须可由会话种子复现。
- 正式上线前，两名未参与本次补题的复核者需独立完成；记忆材料做资源白名单扫描，推演任务运行答案枚举测试。
- 认知访谈必须追问学生实际策略：是否使用目标记忆/关系操作，是否靠位置、首字母、完整标签熟悉度、图形补全、按钮剩余项或唯一顺序假设作答。
