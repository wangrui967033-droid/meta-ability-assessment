# 测评结果收集与管理后台设计

## 目标

将当前仅在浏览器本机保存作答的元能力测评原型，扩展为可部署的机构内部服务：

- 学生在测评网页完成作答后，结果会可靠提交并保存；
- 教师/运营人员登录后台后，可按姓名或手机号检索测评记录；
- 管理员可查看与打印和学生端一致的报告；
- 报告计算在服务端完成，前端不能伪造分数、分类或报告。

首版只面向机构内部管理员。学生和家长没有账号、查询入口或管理权限。

## 不在首版范围内

- 学生/家长登录、短信验证码或自主查阅；
- 多管理员、多角色、权限组和操作审计 UI；
- Excel 批量导入/导出、消息发送或支付；
- 重新定义题库、计分、分类规则或报告视觉；
- 云端多机数据库、实时同步或 BI 看板。

## 架构

```text
学生测评 React 页面 ──┐
                     ├── HTTPS API（Node.js）── SQLite
机构管理 React 页面 ──┘                      ├── 原始作答
                                             ├── 报告快照
                                             └── 备份文件
```

前端继续使用 Vite + React。新增 Node.js HTTP 服务，提供 API 与生产环境下的前端静态文件。OSS 可继续托管只读前端构建产物；部署到带后端的服务器时，前端以配置的 `API_BASE_URL` 调用 API。

所有正式计分、元能力支持状态、学科分类和任务分类都由服务端调用现有领域逻辑生成。前端可在完成页预览，但服务端不会接受前端提交的分数或报告。

## 数据模型

### Assessment

一位学生每次完成测评产生一条独立记录。

| 字段 | 说明 |
| --- | --- |
| `id` | 服务端 UUID，后台详情与打印使用 |
| `student_name` | 报告显示姓名 |
| `phone_encrypted` | 使用部署环境密钥加密的手机号，仅后台详情解密显示 |
| `phone_lookup_hash` | 规范化手机号的 HMAC 摘要，用于完整号码精确查询 |
| `grade` | 高一/高二/高三 |
| `foreign_language` | 英语或日语 |
| `selected_subjects_json` | 学生选择的选考学科 |
| `status` | `submitted`、`processing`、`ready`、`failed` |
| `completed_at` | 完成提交时间 |
| `created_at` / `updated_at` | 审计与排序用途 |
| `bank_version` / `scoring_version` / `mapping_version` | 本次使用的领域配置版本 |

### Assessment payloads

- `responses_json`：原始作答、作答时间、选项顺序审计、记忆间隔信息；
- `report_json`：服务端重新计算生成的 `ReportModel` 快照；
- `report_generated_at`：该快照生成时间；
- `report_revision`：每次后台重新生成后递增。

原始作答与报告快照都保留。新版算法不能默默改写旧报告；管理员显式点击“重新生成”才生成新快照并增加版本号。

### 管理员与会话

首版是单个机构管理员。管理员账号、密码摘要、手机号加密密钥、手机号检索密钥、会话签名密钥都通过环境变量提供，不能写进前端或仓库。

登录成功后服务端签发短期、`HttpOnly`、`Secure`、`SameSite=Lax` 的会话 Cookie。所有 `/api/admin/*` 接口必须验证会话。登出会清除 Cookie。

## API 契约

| 方法与路径 | 调用者 | 行为 |
| --- | --- | --- |
| `POST /api/assessments` | 学生端 | 校验学生信息与完整作答，服务端计分，创建报告快照，返回 `assessmentId` |
| `POST /api/admin/login` | 管理端 | 校验管理员凭据并创建会话 |
| `POST /api/admin/logout` | 管理端 | 失效当前会话 |
| `GET /api/admin/assessments` | 管理端 | 分页列出记录；支持姓名模糊查询和完整手机号精确查询 |
| `GET /api/admin/assessments/:id` | 管理端 | 读取完整记录与报告快照 |
| `POST /api/admin/assessments/:id/regenerate` | 管理端 | 依原始作答使用当前已部署规则生成新报告快照 |
| `GET /health` | 运维 | 返回服务与数据库可用状态，不含个人数据 |

学生提交只接受协议允许的学生资料和题目响应。服务端验证：题库版本、题目位置、每题响应类型、选项标识、作答数量和版本配置。任何分数、分类、报告内容或客户端声明的“完成状态”都忽略并重新计算。

## 页面与流程

### 学生端

1. 入口表单新增必填手机号（仅用于机构查询，不参与评分）；
2. 测评过程继续本地保存草稿，防止中断丢失；
3. 完成后提交到 API；
4. 成功时显示既有报告，页脚显示已保存；
5. 网络或服务端失败时保留本地作答，显示“尚未提交，可重试”，不伪造已保存状态。

### 管理端

1. `/admin/login`：用户名/密码登录；
2. `/admin`：记录列表，列出姓名、脱敏手机号、年级、完成时间、报告状态；
3. 记录列表支持姓名模糊搜索和完整手机号精确搜索、分页；
4. `/admin/assessments/:id`：完整报告与测评完成信息；
5. `/admin/assessments/:id/print`：打印专用页面，复用 `Report` 组件，隐藏管理端导航与控件，浏览器原生打印/另存 PDF；
6. 详情页可显式重新生成报告，展示报告版本和生成时间。

管理端不在列表中显示完整手机号；详情页在已登录状态显示完整手机号。

## 错误处理与隐私

- 不将手机号、原始作答、会话 Cookie 或服务端密钥写入日志、URL、浏览器本地存储或 OSS 静态文件；
- API 返回统一的、对学生可理解的错误文案；后台可得到不含个人信息的错误编号；
- 数据库查询采用参数化查询；
- 管理端页面与 API 设置 `Cache-Control: no-store`；
- 正式环境使用 HTTPS；生产 Cookie 仅在 HTTPS 下传输；
- 数据库每日备份并设置保留期；备份同样按敏感数据存储和访问；
- 首版不提供在线删除记录，避免误删；数据删除/保留策略在正式招生使用前另行确认。

## 配置与部署

部署环境需要以下配置：

```text
PORT
DATABASE_PATH
ADMIN_USERNAME
ADMIN_PASSWORD_HASH
SESSION_SECRET
PHONE_ENCRYPTION_KEY
PHONE_LOOKUP_SECRET
API_BASE_URL
```

开发环境可通过本地 Vite 代理调用后端；生产环境既可由 Node 服务同时承载前端与 API，也可将前端放 OSS、后端放服务器。若两者跨域，服务器仅允许配置过的前端 Origin，并保持 Cookie 的 `Secure`、`SameSite` 和 CORS 配置一致。

## 验收与测试

- 单元测试：学生提交验证、计分重新计算、报告快照、手机号摘要、加密/解密、管理员会话；
- API 集成测试：提交、未登录拒绝、列表检索、详情、重新生成；
- 页面测试：学生提交成功/失败重试、后台登录与查询、打印页；
- 回归测试：沿用已有 300–500 分模拟场景，确保服务端报告的分类与现有领域逻辑一致；
- 人工验证：完成一份测评，从后台检索并打印报告，确认打印内容与学生报告一致。

## 风险与后续演进

SQLite 适合首版、单机机构管理后台。并发管理员较多、需要多服务器部署或长期大规模数据时，迁移到 PostgreSQL/MySQL；数据访问 API 和领域计分模块保持不变。真实学生数据投入使用后，仍需按既有计划校准题库与阈值；本设计不将原型阈值描述为科学常模。
